# Кабинет фотографа и юриста

Отдельное приложение в том же Git-репозитории. PHP 8.2+, SQLite, без сборки. Блог, Telegram и их база не меняются. Корень `files.hunta-zen.ru` должен указывать на отдельную папку сайта; публичная папка блога для этого не подходит.

## Установка

После обновления репозитория на Beget из его корня:

```bash
/usr/local/bin/php8.2 tools/photo_desk_install.php --public=/home/a/altaikemp/files.altaikemp.beget.tech/public_html
```

Установщик проверяет папку до изменений, сохраняет и проверяет копии старых стартовых страниц, устанавливает `index.php`, который подключает модуль из репозитория. База, оригиналы, сессии, кэш и конфиг находятся в закрытом `storage/photo-desk/`, вне публичной папки и Git. Вход фотографа копируется из блога в режиме только чтения, хеш и пароль сохраняются. Если блог недоступен — установщик предлагает прежний вход Орды. Никаких стандартных паролей и публичной регистрации нет.

Текущая роль фотографа — `admin` («Режим разработки»): обе галочки и обе стороны доступны. Создание юриста:

```bash
/usr/local/bin/php8.2 tools/photo_desk_user.php --login=lawyer --role=lawyer
```

Пароль вводится скрыто локально. После проверки обеих ролей ограничить фотографа, указав его действующий логин:

```bash
/usr/local/bin/php8.2 tools/photo_desk_user.php --login=ВАШ_ЛОГИН --role=photographer
```

Роль `admin` можно вернуть той же командой. Юрист меняет запрос, его вложения и галочку закрытия; фотограф — ответ, его вложения и галочку готовности. Обе стороны видят и скачивают все материалы. Готовность подсвечивает карточку и не закрывает её; закрытие юриста имеет приоритет независимо от галочки фотографа. Снять закрытие может юрист. Сохранение текста не меняет галочки автоматически.

## Обновление и копии

Публичная стартовая страница подключает код прямо из репозитория: после git pull файлы копировать не нужно. Перед обновлением модуля:

```bash
/usr/local/bin/php8.2 tools/photo_desk_snapshot.php
```

Копия содержит согласованный SQLite (`integrity_check`), все оригиналы с проверкой хешей и конфиг. Старые копии автоматически не удаляются. Кэш превью воспроизводим. Для восстановления остановить доступ к кабинету, сохранить текущие данные отдельно и восстановить `desk.sqlite`, `files/`, `config.php` из копии с правами 0600/0700. Бэкапы блога не заменяют эту отдельную копию.

## Файлы, ссылки, просмотр

До 12 файлов за одну загрузку и до 50 МБ каждый. Фото, RAW, PDF, DOC/DOCX, TXT, ZIP. Для больших исходников увеличь `upload_max_filesize` (50M), `post_max_size` (650M), `max_file_uploads` (12 или выше) в настройках PHP поддомена, с учётом лимитов тарифа. Интерфейс сообщает об ошибках загрузки; исходники никогда не пережимаются. RAW/TIFF/документы доступны как скачиваемые файлы, браузерные изображения — с превью, увеличением и отдельным скачиванием. GD создаёт небольшие копии для карточек; большие изображения, которые не помещаются в безопасный предел декодирования, выдаются исходниками.

Ссылка сохраняется сразу; приложение автоматически пробует получить превью. Кнопка «Обновить превью ссылки» повторно читает доступные Open Graph метаданные и кэширует картинку локально. Получение ограничено публичными HTTPS-адресами, закреплённым DNS/IP, без прокси, с повторной проверкой адреса на каждом из максимум трёх перенаправлений, с лимитом времени и размера; внутренние адреса запрещены. Защита фотобанка может не отдать превью: ссылка остаётся доступной, картинку можно приложить вручную. Полную внешнюю страницу кабинет не встраивает.

Все файлы и превью требуют входа. На хостинге HTTP перенаправляется на настроенный HTTPS-адрес. Cookie отдельная, без domain, HttpOnly, Secure, SameSite; CSRF у каждого POST, ограничение попыток входа. Поисковая индексация закрыта заголовком и метатегом, сами данные защищены входом. Конфликт revision останавливает перезапись, текст остаётся в форме; файлы надо выбрать повторно. История фиксирует автора, дату, изменения статуса и сохранения. Удаление вложения убирает его из карточки, байты остаются для восстановления и входят в бэкап.

Проверки: `php tests/photo_desk.php`, `python3 tests/photo_desk_http.py`, `node --check photo-desk/public/desk.js`.

## Установка при ограниченном SSH-входе

Если `altaikemp_zen` не видит отдельную папку сайта, кабинет может использовать публичную папку блога. В панели Beget прикрепи `files.hunta-zen.ru` **к тому же сайту, что и `hunta-zen.ru`**. Затем:

```bash
/usr/local/bin/php8.2 tools/photo_desk_install.php --shared
```

Этот режим не пишет стартовые страницы и не требует доступа к другим сайтам. Ранний обработчик в bootstrap направляет только точный хост `files.hunta-zen.ru` в кабинет, до открытия конфигурации и базы блога. Основной домен и CLI продолжают обычную работу. Даже `/admin.php`, `/media.php` и другие PHP-адреса на поддомене проходят в кабинет и не загружают блог. Конфиг и данные кабинета по-прежнему отдельные. Сертификат поддомена должен быть установлен на Beget.

## Компактный интерфейс и превью

Поля запроса свёрнуты под «Изменить запрос»; заголовок и компания остаются в шапке. Формы и вложения уменьшены. Картинки можно вставлять Ctrl+V в любой стороне карточки или перетаскивать на неё; затем нажать сохранение соответствующей стороны.

Получение превью поддерживает HTTPS-перенаправления, относительные адреса, Open Graph, Twitter Image и image_src. На каждом переходе заново проверяется публичность адреса и закрепляется DNS/IP. Если фотобанк ограничивает получение страницы сервером, в «Указать картинку» можно вставить прямой HTTPS-адрес изображения, либо загрузить/вставить саму картинку в запрос. Автоматическое получение не гарантируется для закрытых страниц и сайтов с защитой от роботов.
