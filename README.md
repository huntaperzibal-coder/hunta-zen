# Гена и Винни · hunta-zen

Личный блог и мастерская автора. PHP 8.2+, SQLite, без Composer и сборки фронтенда.

## Что работает

- Лента и страницы историй, обложки и фото в тексте.
- Вход в мастерскую `/admin.php`, черновики и опубликованные записи.
- Автосохранение каждые 5 секунд, защита от перезаписи из другой вкладки.
- Предпросмотр, отдельный анонс для сайта и отдельный текст для Telegram.
- Отправка в канал и обновление того же сообщения. Неопределённый результат сетевого запроса блокирует повтор до ручной проверки.
- Настройки названия и описания, Open Graph, индексация по умолчанию выключена.
- Журнал действий, проверенные резервные копии базы вместе с фотографиями.

Черновик служит и короткой личной заметкой. В первой версии текст вводится в обычном поле; поддержаны абзацы, **жирный текст** и загруженные фотографии. Telegram получает текст и ссылку; отправка фотоальбомов и форматирование постов — отдельное расширение.

## Установка на Beget

Корень домена **обязательно** должен указывать на каталог `public` внутри репозитория. Например, если репозиторий находится в `~/hunta-zen`, корень домена — `~/hunta-zen/public`. В `public` нет базы или секретов. Корень репозитория закрыт дополнительным `.htaccess`, но защита nginx зависит от настройки корня домена.

Нужны PHP 8.2+ и расширения `pdo_sqlite`, `mbstring`, `curl`, `fileinfo`.

```bash
cd /путь/к/репозиторию/hunta-zen
/usr/local/bin/php8.2 tools/setup.php
```

Установка спросит адрес сайта, твой прежний логин. Учётная запись будет в таблице `orda_users`, как в ТОПО. Создаст отдельную пустую базу `storage/blog.sqlite`, каталог фотографий и закрытый конфиг `storage/config.php`. Существующий конфиг не перезаписывает. Установка читает учётную запись указанного логина из базы Орды в режиме только чтения (при необходимости — из прежнего users.json). Сохраняет точный существующий хеш, пароль не меняет. Если исходный сайт недоступен SSH-пользователю, можно ввести тот же действующий пароль локально; новых требований к длине нет. Для входа в админку используй HTTPS после подключения сертификата.

В Beget установи `upload_max_filesize=12M`, `post_max_size=16M` или выше. Иначе PHP может отклонить фотографию до запуска приложения.

## Telegram

В `storage/config.php` укажи `telegram_token` и `telegram_channel` (например `@channel` или числовой ID). Бот должен быть администратором канала с правами публикации и редактирования своих сообщений. Токен не хранится в Git, не выводится в интерфейсе и не должен передаваться в чат.

В редакторе сначала опубликуй историю на сайте. Разверни «Публикация в Telegram», подготовь текст и нажми «Отправить». Ссылка на историю добавится автоматически. Пустое поле означает заголовок и короткий анонс. Для полного текста вставь его в поле канала; лимит — 4096 символов вместе со ссылкой. Сохрани изменения для обновления предпросмотра текста Telegram.

Повторное действие обновляет существующее сообщение в том же канале. При тайм-ауте проверь канал: если сообщение появилось, укажи его номер из ссылки на пост, иначе укажи 0 и подтверди проверку. Сам сайт отправку не повторяет. Отмена публикации на сайте не удаляет сообщение из Telegram.

Документация API: https://core.telegram.org/bots/api#sendmessage и https://core.telegram.org/bots/api#editmessagetext.

## Обновление

```bash
cd /путь/к/репозиторию/hunta-zen
PHP_BIN=/usr/local/bin/php8.2 bash tools/update.sh
```

Скрипт остановится при изменённом локальном коде, создаст копию базы и фото, выполнит `fetch` и обновление `--ff-only`, затем проверит структуру базы. Расхождение истории останавливает обновление; `reset --hard`, `force`, автоматическое удаление и отправка серверных изменений не используются. Конфиг, база, фото и резервные копии исключены из Git.

Перед первой установкой `tools/update.sh` не запускай: резервировать ещё нечего. После обычного `git pull` отдельно выполни `php tools/migrate.php`.

## Резервирование и восстановление

```bash
/usr/local/bin/php8.2 tools/backup.php
```

Копия попадёт в `storage/backups/ДАТА-СЛУЧАЙНЫЙ_СУФФИКС`: согласованный снимок SQLite с `integrity_check` и все фотографии. Копии не удаляются автоматически. Храни копию вне сервера; облачное резервирование ТОПО сюда пока не подключено. Сохраняй закрытый конфиг отдельно.

Восстановление: включи режим обслуживания на хостинге, сохрани текущий `storage` отдельно, замени `blog.sqlite` и `photos` содержимым выбранной копии, проверь владельца файлов и права, запусти `tools/migrate.php`, отключи обслуживание. Приложение использует стандартный журнал SQLite, не WAL.

## Проверки

```bash
find app public tools tests -name '*.php' -exec php -l {} \;
php tests/core.php
php tests/auth.php
python3 tests/integration_http.py
```

HTTP-проверка запускает временный PHP-сервер только на localhost и работает с временной базой. Реальных сообщений в Telegram не отправляет. CI проверяет PHP 8.2 и 8.3.

## Происхождение решений

За основу взяты принципы из `huntaperzibal-coder/altai-topo` (прочитан коммит `01a87a5cb2cd6861de02eb0501c4f28118e2ead5`): PDO/SQLite и внешние ключи, один контроль входа перед обработчиками, черновик/публикация и уникальные адреса. Реализация адаптирована под личный блог. ТОПО, его данные и настройки резервирования не изменялись и не копировались. Учётная запись автора переносится отдельно по выбранному логину без изменения пароля и исходного сайта.

## Прежний пароль и механизм входа Орды

`app/orda_auth.php` адаптирует функции Орды: `ordaFindUser`, `ordaLoginSession`, `ordaGuardPasswordFingerprint`, `ordaThrottle*`. Логины сопоставляются без учёта регистра. Пользователи находятся в `orda_users`; удаление пользователя или смена его хеша отзывает существующую сессию. Сессии сайтов отдельные: это перенос доступа, а не общий вход между доменами.

Если первая версия уже установлена, `tools/migrate.php` сохраняет её существующий доступ без смены пароля. Чтобы перенести именно учётную запись других сайтов:

```bash
/usr/local/bin/php8.2 tools/use-existing-author.php
```

Скрипт спросит твой прежний логин, попробует прочитать его из `/home/a/altaikemp/topo-altai.ru/public_html`. Для другого расположения задай `HUNTA_TOPO_ROOT`. К базе источника открывается подключение `mode=ro`. Переносится один выбранный аккаунт, хеш не печатается и не записывается в Git. Если читать источник запрещено, не меняй права: введи прежний пароль в терминале. Старые аккаунты блога этот скрипт не удаляет.
