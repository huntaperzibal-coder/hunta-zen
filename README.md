# Гена и Винни · hunta-zen

Личный блог и мастерская автора. PHP 8.2+, SQLite, без Composer и сборки фронтенда.

## Что работает

- Лента и страницы историй, обложки и фото в тексте.
- Вход в мастерскую `/admin.php`, черновики и опубликованные записи.
- Автосохранение каждые 5 секунд, защита от перезаписи из другой вкладки.
- Предпросмотр, отдельный анонс для сайта и отдельный текст для Telegram.
- Отправка в канал и обновление того же сообщения. Неопределённый результат сетевого запроса блокирует повтор до ручной проверки.
- Настройки названия и описания, Open Graph, индексация по умолчанию выключена.
- Журнал действий, проверенные резервные копии базы вместе с фотографиями.

Черновик служит и короткой личной заметкой. Текст редактируется визуально в TinyMCE: заголовки, жирный и курсив, списки, цитаты, ссылки, таблицы, фотографии с подписями, поиск, отмена и полноэкранный режим. Telegram получает полный рассказ с форматированием, одну иллюстрацию и ссылку; отправка — отдельной кнопкой или по расписанию.

## Установка на Beget

Корень домена **обязательно** должен указывать на каталог `public` внутри репозитория. Например, если репозиторий находится в `~/hunta-zen`, корень домена — `~/hunta-zen/public`. В `public` нет базы или секретов. Корень репозитория закрыт дополнительным `.htaccess`, но защита nginx зависит от настройки корня домена.

Нужны PHP 8.2+ и расширения `pdo_sqlite`, `mbstring`, `curl`, `fileinfo`, `dom`.

```bash
cd /путь/к/репозиторию/hunta-zen
/usr/local/bin/php8.2 tools/setup.php
```

Установка спросит адрес сайта, твой прежний логин. Учётная запись будет в таблице `orda_users`, как в ТОПО. Создаст отдельную пустую базу `storage/blog.sqlite`, каталог фотографий и закрытый конфиг `storage/config.php`. Существующий конфиг не перезаписывает. Установка читает учётную запись указанного логина из базы Орды в режиме только чтения (при необходимости — из прежнего users.json). Сохраняет точный существующий хеш, пароль не меняет. Если исходный сайт недоступен SSH-пользователю, можно ввести тот же действующий пароль локально; новых требований к длине нет. Для входа в админку используй HTTPS после подключения сертификата.

В Beget установи `upload_max_filesize=12M`, `post_max_size=16M` или выше. Иначе PHP может отклонить фотографию до запуска приложения.

## Telegram

Подключение: **Дао → Telegram**. Вставь токен из BotFather и @имя канала (для закрытого канала — числовой ID `-100…`). Бот должен быть администратором с правами публикации и редактирования. Кнопка проверяет бота, канал и права через getMe/getChat/getChatMember, ничего не публикуя. Подключение сохраняется атомарно в закрытом `storage/telegram-connection.php` с правами 0600; токен не возвращается в форму и не входит в Git. Старые параметры `storage/config.php` поддерживаются. Канал закрепляется по числовому ID.

В редакторе сначала опубликуй историю на сайте, затем отдельно нажми **«Отправить в Telegram сейчас»**. По умолчанию уходит весь рассказ, название, подпись линии: «⚙️ Так устроено · Дао Гены» / «☯️ Так суждено · Дао Винни» (название жирным, подпись курсивом) и ссылка на оригинал. Пустое поле «Другой текст» означает полный рассказ с жирным, курсивом, подчёркиванием, зачёркиванием, цитатами и ссылками; заполненное поле — альтернативный обычный текст. Размеры шрифтов, цвета и таблицы Telegram не воспроизводит.

Обложка (или первая встроенная фотография) загружается прямо в Telegram. Если полный текст со ссылкой помещается в 1024 UTF-16 единицы, он отправляется подписью; иначе фото и полный текст отдельными сообщениями. Длинный текст делится по абзацам/строкам/словам с корректными UTF-16 смещениями форматирования, без обрезки. Фото — до 10 МБ; остальные встроенные фотографии в канал не копируются.

Повторное нажатие обновляет известные сообщения в выбранном канале, а лишние части после сокращения текста удаляет. При изменении числа частей новые сообщения добавляются в конец канала. При тайм-ауте система блокирует повтор: проверь указанную часть в канале, введи её номер из ссылки или 0, если её нет, подтверди проверку и заверши отправку. Уже известные части обновляются, не дублируются. Возврат в черновики не удаляет опубликованные сообщения из Telegram.

**Отложенная отправка:** выбери дату/время (Новосибирск, UTC+7) и нажми «Запланировать». Сохраняется текущая версия текста, фото, канал и отпечаток бота. Изменения текста не меняют задание: назначь отправку повторно, чтобы заменить снимок. Отмена доступна до начала работы. Отправка сейчас отменяет ожидающее задание этой записи. Возврат в черновики или смена подключения останавливают задание. Сбой, зависшее задание или неизвестный результат не вызывают автоматического повторения.

В Beget → Cron один раз добавь задачу **каждую минуту**:

```sh
/usr/local/bin/php8.2 /home/a/altaikemp/hunta-zen.ru/repo/tools/telegram_worker.php
```

Если конфиг расположен нестандартно, добавь перед командой `env HUNTA_CONFIG=/absolute/path/config.php`. Обработчик работает только в CLI; закрытые HTTP/SSH методы для публичного запуска не создаются. В разделе Telegram показаны очередь, состояние доставки и время последнего запуска. Без cron задания остаются в очереди. Минуты GitHub Actions не расходуются.

Проверка без реальной сети: `php tests/telegram.php`. Документация: https://core.telegram.org/bots/api.

## Обновление

```bash
cd /путь/к/репозиторию/hunta-zen
PHP_BIN=/usr/local/bin/php8.2 bash tools/update.sh
```

Скрипт остановится при изменённом локальном коде, создаст копию базы и фото, выполнит `fetch` и обновление `--ff-only`, затем проверит структуру базы. Расхождение истории останавливает обновление; `reset --hard`, `force`, автоматическое удаление и отправка серверных изменений не используются. Конфиг, база, фото и резервные копии исключены из Git.

Перед первой установкой `tools/update.sh` не запускай: резервировать ещё нечего. После обычного `git pull` отдельно выполни `php tools/migrate.php`.

## Резервирование и восстановление

```bash
/usr/local/bin/php8.2 tools/backup.php
```

Копия попадёт в `storage/backups/ДАТА-СЛУЧАЙНЫЙ_СУФФИКС`: согласованный снимок SQLite с `integrity_check` и все фотографии. Копии не удаляются автоматически. Храни копию вне сервера; облачное резервирование ТОПО сюда пока не подключено. Сохраняй закрытый конфиг отдельно.

Восстановление: включи режим обслуживания на хостинге, сохрани текущий `storage` отдельно, замени `blog.sqlite` и `photos` содержимым выбранной копии, проверь владельца файлов и права, запусти `tools/migrate.php`, отключи обслуживание. Приложение использует стандартный журнал SQLite, не WAL.

## Происхождение решений

За основу взяты принципы из `huntaperzibal-coder/altai-topo` (прочитан коммит `01a87a5cb2cd6861de02eb0501c4f28118e2ead5`): PDO/SQLite и внешние ключи, один контроль входа перед обработчиками, черновик/публикация и уникальные адреса. Реализация адаптирована под личный блог. ТОПО, его данные и настройки резервирования не изменялись и не копировались. Учётная запись автора переносится отдельно по выбранному логину без изменения пароля и исходного сайта.

## Прежний пароль и механизм входа Орды

`app/orda_auth.php` адаптирует функции Орды: `ordaFindUser`, `ordaLoginSession`, `ordaGuardPasswordFingerprint`, `ordaThrottle*`. Логины сопоставляются без учёта регистра. Пользователи находятся в `orda_users`; удаление пользователя или смена его хеша отзывает существующую сессию. Сессии сайтов отдельные: это перенос доступа, а не общий вход между доменами.

Если первая версия уже установлена, `tools/migrate.php` сохраняет её существующий доступ без смены пароля. Чтобы перенести именно учётную запись других сайтов:

```bash
/usr/local/bin/php8.2 tools/use-existing-author.php
```

Скрипт спросит твой прежний логин, попробует прочитать его из `/home/a/altaikemp/topo-altai.ru/public_html`. Для другого расположения задай `HUNTA_TOPO_ROOT`. К базе источника открывается подключение `mode=ro`. Переносится один выбранный аккаунт, хеш не печатается и не записывается в Git. Если читать источник запрещено, не меняй права: введи прежний пароль в терминале. Старые аккаунты блога этот скрипт не удаляет.

## Оболочка админки из ТОПО

Админка использует исходный `stili_orda.css`, семь начертаний Manrope, собственные логотипы и иконки «Дао». Базовый CSS скопирован без изменений. Происхождение и SHA ресурсов записаны в `docs/orda-origin.json`.

Разметка оболочки адаптирована из `adminka/orda.php`, меню — из `render_orda_menu.php`, форма входа — из `adminka/login.php`. Слева — Дао и разделы блога, справа — рабочая страница. Меню открывает обычные страницы в том же документе: предупреждение о несохранённом тексте работает при переходах. На телефоне меню раскрывается кнопкой.

Из исходных скриптов подключены подтверждение выхода и сообщение о сохранении. Ctrl+S/Cmd+S сохраняет рабочую форму; поиск формы адаптирован, чтобы не активировать выход из бокового меню. Дополнительный `orda_blog.css` отвечает за размещение редактора и адаптацию блога; свою палитру он не вводит. Публичное оформление блога остаётся отдельным.

Админка называется «Дао». На сайте — янтарный знак разговора, в админке — фиолетовый знак двух половин круга. Имя публичного блога остаётся «Гена и Винни». SVG, favicon (SVG/PNG/ICO), значки для домашнего экрана и два манифеста находятся в `public/assets/brand`, `site.webmanifest` и `admin.webmanifest`. Пунктам меню назначены собственные контурные иконки; старый логотип ТОПО больше не используется.

PNG и ICO воспроизводятся командой `python3 tools/build_brand.py` (нужен Pillow). На сервере запускать сборку не требуется: готовые файлы хранятся в Git.

## Одна команда, как topo-sync.sh

Один раз после получения этого обновления:

```bash
cd /home/a/altaikemp/hunta-zen.ru/repo
/usr/local/bin/php8.2 tools/install_sync.php
```

Дальше из любой папки:

```bash
~/zen-sync.sh
```

Скрипт работает с `main`: проверяет сохранность кода, делает резервную копию, получает изменения (`fetch`, до трёх попыток), переносит локальные коммиты поверх свежей `origin/main` (`rebase`), обновляет структуру базы и выполняет `push`. При гонке с новым коммитом повторяет получение и push до трёх раз. `force`, автоматическое добавление файлов и создание коммитов не используются. Несохранённый код или конфликт останавливают работу с сообщением. База, фотографии, пароли и настройки остаются вне Git.

`tools/update.sh` остаётся вариантом только для получения обновлений без push. `tools/install_sync.php` создаёт персональный запускатель в домашней папке; прежний одноимённый скрипт при замене сохраняется рядом.

## Визуальный редактор

Локальная копия TinyMCE 8.5.0 из ТОПО находится в `public/assets/tinymce` вместе с уведомлениями об авторских правах и лицензии. Внешняя сеть или ключ Tiny Cloud не нужны. Интерфейс русский. Код интеграции — `public/assets/js/editor.js`.

Кнопка «Фото» вставляет одну или несколько фотографий в позицию курсора. Также доступны перетаскивание, вставка из буфера и стандартный диалог изображения с подписью. Загрузка идёт через `editor-upload.php`, требует входа и CSRF. Сохранение ждёт завершения загрузок. Ctrl+S работает и внутри поля редактора, автосохранение — каждые пять секунд.

Старые обычные тексты и прежние фотографии преобразуются в визуальный вид при открытии; исходные записи не меняются до сохранения. Новые форматированные тела имеют маркер `<!--dao:rich-v1-->`, отдельная миграция базы не требуется. Сервер принимает только разрешённую разметку; изображения — только загруженные на этот сайт. Скрипты, iframe и обработчики событий не сохраняются. Для обработки HTML нужно стандартное PHP-расширение DOM. Анонсы сайта и Telegram извлекают обычный текст.

Проверки форматированного текста: `php tests/rich_text.php`.

## Категории и раскрытие редактора

Две категории: «Диалоги Винни» и «Диалоги Гены». Категория выбирается над текстом и сохраняется вместе с записью, в том числе автоматически. В списке админки и на сайте доступны фильтры. Старые записи остаются без категории до ручного выбора. Таблицы `categories` и `post_categories` создаются идемпотентно через обычное обновление; существующие тексты не переписываются.

Текст в редакторе — 16 px. TinyMCE Autoresize увеличивает поле под содержимое: начальная высота 760 px на компьютере и 480 px на телефоне, максимум 6000 px. Полноэкранный режим сохранён. Плагин взят из той же локальной сборки ТОПО.


## Иллюстратор через OpenRouter

В Дао появился раздел «Иллюстратор»: ключ, модели читателя и художника, общий стиль, описания героев, три референса и дневной лимит вариантов. Ключ вводится только в админке и хранится в `storage/openrouter-key.php` с правами 0600, отдельно от базы и Git. Пустое поле сохраняет прежний ключ. Для ввода секрета используй HTTPS. Описание героев и референсы можно добавить позже.

После обычного `~/zen-sync.sh` один раз подключи обработчик из каталога репозитория:

```sh
PHP_BIN=/usr/local/bin/php8.2 bash tools/install_illustrator.sh
```

Скрипт сохраняет остальные cron-задания и идемпотентно добавляет свой запуск раз в минуту. Если хостинг запрещает управление crontab, добавь через панель Beget задачу `php8.2 /home/a/altaikemp/hunta-zen.ru/repo/tools/illustrator_worker.php` (используй полный путь к PHP хостинга). В настройках виден последний запуск. Worker берёт эксклюзивную блокировку и обрабатывает одну задачу за запуск; параллельный cron сразу выходит.

В редакторе: пожелания → «Проиллюстрировать» → история вариантов → «На обложку» или «Добавить в конец текста». Любая из этих кнопок сначала сохраняет текущий текст с проверкой revision. Иллюстрация создаётся по неизменяемому снимку полного текста, выбранным в момент запуска моделям, стилю и референсам. История не переписывает запись автоматически. Результат виден только автору, пока картинка не использована в опубликованной записи. Поле редактора не заменяется при обновлении состояния генерации.

Используются официальные API OpenRouter: `/api/v1/chat/completions` для разбора текста и `/api/v1/images` для одной картинки. Модель художника должна поддерживать [Image API](https://openrouter.ai/docs/guides/overview/multimodal/image-generation), а при добавлении референсов — `input_references`. Идентификаторы моделей редактируются без изменения кода. Текст до 40 000 символов передаётся целиком, более длинный не обрезается, а отклоняется. На каждый вариант расходуется баланс OpenRouter: запрос читателю и художнику. Дневной лимит ограничивает число вариантов, а не доллары; финансовый предел настраивается у ключа OpenRouter. Стоимость показывается, когда API её сообщает.

В базе новая таблица `illustration_jobs`, миграция идемпотентна. Фотографии и референсы сохраняются в `storage/photos`, входят в обычную резервную копию. Ключ нужно отдельно сохранить безопасным способом. Повторы после ошибок и прерываний не выполняются автоматически: сначала проверь журнал OpenRouter, затем явно закажи новый вариант. Не запускай worker через HTTP.

Проверки без внешних запросов и расходов: `php tests/illustrator.php` (снимки, дубли, приватность ключа, вставка с revision, ошибки, отсутствие повторов и референсы). Реальный платный прогон выполняется автором после подключения ключа; локально проверен подставной транспорт.


Подсказки редактора открываются при наведении на инструменты и поля или при переходе клавишей Tab; Escape закрывает подсказку. Ссылка «Иллюстрации ↓» над заголовком ведёт к генератору под текстом. Скрипт установки cron через Bash работает и при запрещённом PHP `exec()`; при отказе планировщика показывает причину и команду для панели Beget, сохраняя существующие задания. Старый PHP-установщик теперь выводит ошибку в терминал и предлагает Bash вместо молчаливого выхода 255.

Проверка доступа к OpenRouter без генерации и списаний: `php tools/illustrator_diagnose.php`. Скрипт выполняет только GET публичного каталога `/models` и проверки ключа `/key`; ключ и содержимое успешных ответов не печатает. Показывает HTTP-статус и тип ответа. Подсказки появляются после паузы 700 мс, исчезают при клике/вводе и не открываются от фокуса мышью.


## Обработка иллюстраций в GitHub Actions

Сайт и SQLite остаются на Beget. Workflow `Story illustrator` получает задания и референсы через SSH, выполняет читателя/художника и возвращает результат через тот же SSH-мост. Черновики, ключи, референсы и картинки не записываются в Git, артефакты или публичные логи. OpenRouter-ключ передаётся из закрытого storage по SSH, хранится во временной папке runner с правами 0700/0600 и удаляется при завершении. Токен запуска GitHub хранится отдельно в `storage/illustrator-github.php` (0600).

После `~/zen-sync.sh` выполни один раз из репозитория:

```sh
PHP_BIN=/usr/local/bin/php8.2 HUNTA_SSH_USER=altaikemp_zen bash tools/install_illustrator_actions.sh
```

`HUNTA_SSH_HOST` по умолчанию `vortex.beget.com`; для другого сервера задай свой адрес. Скрипт создаёт `storage/illustrator-actions-key`, добавляет в `~/.ssh/authorized_keys` отдельную строку с `restrict,command=...illustrator_bridge.php`, сохраняет предыдущий authorized_keys, делает проверенную резервную копию базы и включает режим `actions`. Существующие ключи не удаляются. Режим не включается, если не удалось получить проверенные публичные ключи сервера: сначала читаются локальные `/etc/ssh/ssh_host_*_key.pub`, затем пробуется исключительно локальный SSH через loopback. Если ключи недоступны, перенеси уже проверенную запись со своего компьютера в `storage/illustrator-actions-known-hosts` и повтори установку. Не заменяй проверку хоста на `StrictHostKeyChecking=no`.

В GitHub → Settings → Secrets and variables → Actions добавь:

| Раздел | Имя | Значение |
| --- | --- | --- |
| Secrets | `HUNTA_SSH_KEY` | Содержимое `storage/illustrator-actions-key` целиком |
| Secrets | `HUNTA_SSH_KNOWN_HOSTS` | Содержимое `storage/illustrator-actions-known-hosts` |
| Variables | `HUNTA_SSH_TARGET` | `altaikemp_zen@vortex.beget.com` (или адрес из настройки сайта) |

В Дао → Иллюстратор находятся инструкция и кнопки скачивания этих файлов. Приватный ключ скачивается через админку только по HTTPS; иначе используй защищённый файловый менеджер Beget. Не присылай ключи в чат. Для запуска из редактора добавь в Дао отдельный Fine-grained personal access token GitHub: только `hunta-zen`, Repository permissions → Actions → Read and write. Пустое поле сохраняет прежний токен. Токен не нужен для резервного ручного запуска на GitHub → Actions → Story illustrator → Run workflow.

Workflow запускается только через workflow_dispatch на main, не через PR и не по расписанию. Он не имеет прав записи в Git. Глобальная concurrency исключает параллельные обработчики. Один запуск обрабатывает до 10 ожидающих задач, прекращает брать новые после 18 минут и ограничен 30 минутами; обычно запуск завершается после одного варианта и пустой очереди. При остатке очереди есть кнопка «Запустить ожидающую очередь» в редакторе. Ожидание в очереди GitHub не меняет текст записи.

Новая таблица `illustration_remote_leases` хранит хеш одноразового разрешения на результат. Повторная доставка уже сохранённого результата идемпотентна. SSH-мост не исполняет SSH_ORIGINAL_COMMAND и разрешает только claim/progress/finish; он не даёт интерактивный SSH, SFTP, туннели или произвольные команды. Ошибки SSH и процесса не печатают входные пакеты. После обрыва платный запрос не повторяется. Просроченная через 30 минут задача получает unknown при следующем обмене или запуске прежнего cron.

Существующий Beget cron можно оставить: в режиме Actions он только отмечает просроченные задания и не вызывает OpenRouter. Для возврата к локальной обработке установи setting `illustrator_backend=local`; текущие активные задачи сначала проверь в GitHub/OpenRouter.

Проверки без сетевых запросов и списаний: `python3 tests/illustrator_remote.py` (реальный PHP-мост, локальный runner с подставным провайдером, защита разрешений, повторная доставка и сохранность текста), `python3 tests/illustrator_actions_install.py` (установка в изолированную SSH-папку, сохранение старых ключей, права и резервные копии). Сквозной SSH до Beget и настоящая генерация проверяются после однократного добавления секретов владельцем.
